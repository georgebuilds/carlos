guides · mcp

Bring your own tools.

Model Context Protocol servers extend carlos with extra tools (GitHub, Postgres, Linear, anything that speaks MCP). Manage them from your shell with carlos mcp, which deliberately mirrors claude mcp so a command copied from the internet works by swapping the binary name. Check status from inside a session with the /mcp panel.

Two surfaces, one model

carlos follows Claude Code's split:

  • The carlos mcp CLI manages servers: add, list, get, remove. This is where you wire a server up.
  • The in-session /mcp panel shows configured servers, whether each connected this session, and how many tools it contributed. It is a status view, not a place to add servers.

Servers are read once at startup, so any add or remove takes effect on the next carlos start.

From the CLI

Drop the binary name in front of any claude mcp add recipe:

shell 
# stdio server (the common case). Put the server command after `--`.
carlos mcp add github -e GITHUB_TOKEN=ghp_xxx -- npx -y @modelcontextprotocol/server-github

# remote servers by URL
carlos mcp add --transport sse linear https://mcp.linear.app/sse
carlos mcp add --transport http notion https://mcp.notion.com/mcp -H "Authorization: Bearer xxx"

# add from a JSON blob (Claude Code's add-json shape)
carlos mcp add-json weather '{"type":"stdio","command":"npx","args":["-y","weather-mcp"]}'

# inspect + remove
carlos mcp list
carlos mcp get github
carlos mcp remove github

The add flags match claude mcp add:

flagwhat
-t, --transportstdio (default), sse, or http. For sse/http the positional after the name is the URL.
-e, --env KEY=valueEnvironment variable for a stdio server. Repeatable.
-H, --header "Name: value"HTTP header for an sse/http server. Repeatable.
--Everything after it is the verbatim stdio command and its arguments.
-f, --frame <name>carlos-native: gate the server to a frame. Repeatable. Omit to enable everywhere.
-s, --scopeAccepted for paste compatibility and ignored: carlos uses per-frame gating, not Claude Code's local/project/user scopes. Use --frame instead.

carlos's MCP client does not do OAuth, so Claude Code's --client-id / --client-secret / --callback-port flags are accepted and ignored with a note rather than failing the paste.

From within the TUI

Type /mcp in a session to open the panel. It lists every server configured for the active frame with a live marker: a filled dot for connected, an open dot for not, plus the per-server tool count and an x/y connected summary.

in a carlos session 
# show servers + live status for this frame
/mcp
/mcp list

# quick edits without leaving the chat (same config the CLI writes)
/mcp add github npx -y @modelcontextprotocol/server-github
/mcp add docs --http https://example.com/mcp
/mcp remove github

/mcp help

The slash edits and the carlos mcp CLI write the same ~/.carlos/config.yaml, so they compose freely. As with the CLI, a newly added server connects on the next start.

The config block

Both surfaces edit the mcp.servers list in ~/.carlos/config.yaml. You can also hand-edit it:

~/.carlos/config.yaml 
mcp:
  servers:
    - name: github
      command: npx
      args: ["-y", "@modelcontextprotocol/server-github"]
      env:
        GITHUB_TOKEN: ghp_...
      frames: ["personal"]   # optional gate; omit to enable everywhere
    - name: linear
      transport: sse
      url: https://mcp.linear.app/sse

Each server's tools register under <server>__<tool> (e.g. github__list_issues) and flow through the standard layered approval policy. The optional frames field is the gate: a server with no frames is available in every frame; otherwise it is restricted to the listed ones. See frames for the gating model.

Importing from Claude Code

Onboarding offers to import the MCP servers already configured in your Claude Code setup. Re-run it any time with carlos onboard --only mcp to pick servers off that list instead of re-typing them.
